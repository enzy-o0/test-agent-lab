# 02. 커버리지 100%가 말해주지 않는 것

3단계에서 뮤테이션 스코어를 처음 쟀다. 이 레포가 세운 논지 —
*"커버리지는 테스트의 검증 강도를 말해주지 않는다"* — 의 실측값이 여기서 나왔다.

측정: 사람이 쓴 테스트 28개, 뮤턴트 152개, Stryker 8.2.6 + vitest 1.6.1.

## 한 줄에서 갈린 것

`src/widgets/Options/ui/ScoopOptions/ScoopOptions.tsx` 40번 줄이다.

```tsx
<img style={{ width: '75%' }} src={`${URL}/${imagePath}`} alt={`${name} scoop`} />
```

Stryker 가 이 한 줄의 두 속성을 각각 변형했다. 결과가 정반대다.

| 속성 | 뮤턴트 | 결과 |
|---|---|---|
| `alt={`${name} scoop`}` | 문자열 치환 | 🟢 **killed** — 테스트가 즉시 잡는다 |
| `src={`${URL}/${imagePath}`}` | `""` 로 치환 | 🔴 **생존** — 아무 테스트도 눈치채지 못한다 |

**이미지 주소를 통째로 빈 문자열로 바꿔도 28개 테스트가 전부 통과한다.**

이건 [발견 3](00-베이스라인-발견.md)이 말한 그것이다. 문제의 테스트 이름은
`displays image for each scoop option from server` 이고, 개수와 `alt` 는 확인하지만
`src` 는 확인하지 않는다.

주목할 점은 **아무도 Stryker 에게 여기를 보라고 알려주지 않았다**는 것이다.
발견 3 은 사람이 소스를 읽다 찾은 것이고, 뮤테이션 스코어는 같은 결함을
독립적으로 재발견했다. 지표가 실제로 작동한다는 뜻이다.

## 커버리지는 이 차이를 볼 수 없다

앱 컴포넌트 다섯 개다. **커버리지는 전부 100%다.**

| 파일 | Statements | Branch | 뮤테이션 스코어 |
|---|---|---|---|
| `Options.tsx` | 100% | 100% | **90.91%** |
| `SummaryForm.tsx` | 100% | 100% | **75.00%** |
| `ScoopOptions.tsx` | 100% | 100% | **54.84%** |
| `ToppingOption.tsx` | 100% | 100% | **54.55%** |
| `AlertBanner.tsx` | 100% | 100% | **45.45%** |

커버리지 열은 상수다. 뮤테이션 열은 **45%p 범위로 흩어진다.**

같은 100%가 어떤 파일에서는 열에 아홉을 잡고 어떤 파일에서는 절반도 못 잡는다.
커버리지는 이 다섯 파일을 구분할 정보를 하나도 담고 있지 않다 —
"좋은 테스트"와 "실행만 한 테스트"가 같은 숫자로 보고된다.

전체로 보면 **커버리지 97.62% / 뮤테이션 75.00%, 간격 22.62%p** 다.
파일 단위로 내려가면 간격은 최대 54.55%p 까지 벌어진다.

## 살아남은 뮤턴트 38개는 무엇이었나

가장 흔한 두 부류다.

**1. 화면에 그려지지만 아무도 단언하지 않는 값** (가장 많음)
`src`, `style`, `max`, `controlId` 같은 속성. 렌더 트리를 지나가므로 커버리지는
100%가 되고, 테스트는 요소의 존재와 접근성 이름까지만 본다.

**2. 경계 조건** — `ScoopOptions.tsx` 21번 줄의 범위 검사가 그렇다.
```
currentValueFoat < 0 || currentValueFoat > 10   →   0 < currentValueFoat / currentValueFoat < 10
```
비교 방향을 뒤집어도 통과한다. 경계값(0, 10, 10.5)을 찌르는 테스트가 없다.

`AlertBanner.tsx` 가 45.45% 로 가장 낮은 건 성격이 다르다 —
기본 인자(`message`, `variant`)와 스타일 속성이 전부 미검증이다.
이 컴포넌트는 다른 테스트에 **곁다리로 렌더될 뿐** 직접 검증받은 적이 없는데,
커버리지는 그걸 100%로 보고한다.

## 4단계에 넘기는 것

살아남은 뮤턴트 38개가 `agent/critique.ts` 의 입력이다. 커버리지 갭과 달리
**"여기가 비어 있다"가 아니라 "이 변경을 아무도 잡지 못했다"** 는 구체적인 근거라,
에이전트에게 훨씬 나은 지시가 된다.

2단계 실험의 판정 기준도 여기서 나온다. 에이전트가 쓴 테스트를 커버리지로만 보면
100%를 쉽게 채우고 "좋아졌다"고 쓰게 되는데, 위 표가 그 결론이 왜 무의미한지 보여준다.
**커버리지 동률에 뮤테이션 스코어가 낮으면 진 것이다.**
