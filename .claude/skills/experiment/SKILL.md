# 에이전트 실험 1회

실험은 **반드시 롤백까지 끝나야** 1회다. 중간에 멈추면 픽스처가 오염된 채 남아
다음 실험의 기준선이 망가진다.

## 0. 전제 확인

```bash
git status --short
```

작업 트리가 더러우면 멈추고 사용자에게 알린다. 실험은 깨끗한 상태에서만 시작한다.

기준선 숫자가 없으면 `baseline` 스킬을 먼저 돌린다.

## 1. 실험 조건을 먼저 적는다

`reports/run-<설명>.md` 를 **실행 전에** 만들고 아래를 적는다.

- 무엇을 검증하려는 실험인가 (한 문장)
- 어떤 테스트 파일을 제거하는가
- 에이전트에 무슨 프롬프트/모델/설정을 쓰는가
- 성공 판정 기준은 무엇인가

나중에 적으면 결과에 맞춰 기준을 바꾸게 된다. 순서를 지킨다.

## 2. 테스트 제거

제거 범위를 좁게 잡는다. 한 번에 전부 지우면 어디서 실패했는지 안 보인다.

```bash
cd fixtures/sundaes
rm src/pages/entry/test/Options.test.tsx   # 예시 — 대상만 지운다
```

**소스는 절대 건드리지 않는다.** `CLAUDE.md` 픽스처 불변 원칙 참고.

## 3. 에이전트 실행

`agent/` 의 해당 스크립트를 돌린다. 실행 중 다음을 수집한다.

- 소요 시간
- 토큰 사용량
- 재시도 횟수 (자가수복 루프가 몇 번 돌았는지)

## 4. 측정

`baseline` 스킬의 측정 절차를 그대로 따른다. 같은 절차를 써야 비교가 된다.

기준선과 나란히 놓고 표로 만든다.

| | 사람이 쓴 테스트 | 에이전트 | 차이 |
|---|---|---|---|
| 테스트 수 | | | |
| Statements | | | |
| Branch | | | |
| 뮤테이션 스코어 | | | |

**커버리지가 같아도 뮤테이션 스코어가 낮으면 진 것이다.** 이 레포의 판정 기준이다.

## 5. 정성 기록

숫자 밖에서 눈에 띈 것을 `docs/` 에 남긴다. 이게 이 레포의 실질적 산출물이다.

- 에이전트가 쓴 나쁜 테스트 패턴 (assertion 없는 렌더 테스트, 구현 세부사항 검증 등)
- 살아남은 뮤턴트와 그 이유
- 자가수복이 잘못된 방향으로 간 사례 — 테스트를 고치는 대신 기대값을 실제값에 맞춰버리는 식

특히 마지막 항목을 주의해서 본다. 에이전트가 테스트를 "통과시키려고" 검증을
약화시키는 건 흔하고, 커버리지로는 절대 안 잡힌다.

## 6. 롤백

```bash
cd fixtures/sundaes
git checkout -- src/
git status --short .   # 비어 있어야 한다
```

비어있지 않으면 사용자에게 알린다. 임의로 `git clean` 하지 않는다 —
에이전트가 만든 산출물이 아직 기록되지 않았을 수 있다.

## 7. 커밋

`reports/` 와 `docs/` 변경만 커밋한다. 픽스처 변경이 섞이면 안 된다.

```bash
git add reports/ docs/
git commit
```

메시지에는 결론을 한 줄로 적는다. "실험 실행"이 아니라
"에이전트 테스트는 커버리지 동률이지만 뮤테이션 스코어 31%p 낮음"처럼.
